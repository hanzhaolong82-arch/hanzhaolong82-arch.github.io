SYSTEM OVERVIEW

我交付的不是一张 IP 图，
而是一套教学角色系统。

角色本身、角色行为和角色所在的 UI 框架必须一起设计。否则角色只是装饰，无法成为学生可依赖的老师。

01
IP CHARACTER

先定义老师，
再设计形象。

IP 不是可爱的装饰物，而是一个要在学生学习受阻、完成、等待等时刻承担教学职责的角色。

01 · ROLE POSITIONING

他不是吉祥物，
是学生身边的教学伙伴。

定位决定后续每一个视觉判断：角色要亲和，但不能幼态；要专业，但不能压迫；要有科技感，但不能像一个冷冰冰的机器人。

PERSONALITY

耐心、聪明、不抢话

角色先观察和引导，再给出帮助，不直接夺走学生的思考过程。

RELATIONSHIP

像老师，也像陪伴者

能讲解知识，也能在完成后给予明确、克制的正向反馈。

VISUAL ROLE

成为课堂中的第二视觉层

角色始终在场，但题目、输入和反馈优先级高于角色。

02 · CHARACTER DNA

把形象拆成
可被锁定的角色 DNA。

先锁定不可变的识别锚点，再允许姿态、表情、动作和场景变化，才能保证后续资产扩展时始终是同一位老师。

识别锚点 01黑色卷发与圆框眼镜，建立聪明、可信赖的印象。
识别锚点 02蓝白学院服与 π 标识，让教学身份进入视觉细节。
识别锚点 03亲和比例和柔和表情，避免角色过度卡通或过度成熟。
LOOK

专业但不严肃

降低老师形象的距离感，让学生愿意开口求助。

POSE

自然但不抢镜

姿态始终服务于当前教学任务和内容区。

VOICE

启发而非播报

用一句问题带学生继续思考，而不是替他完成答案。

03 · ASSET PRODUCTION PATH

先控制一致性，
再扩展角色资产。

无论最终由 AIGC、3D、插画还是协作团队生产，设计师都需要先建立稳定输入、明确筛选标准，并在 UI 中持续校验。

01

角色简报

定义性格、受众、教学职责和品牌约束。

02

锁定 DNA

确定不可变的脸型、服装、发型、眼镜和标识。

03

基础形象

验证比例、材质、光线和单人识别度。

04

状态扩展

围绕教学任务生成姿态、表情、手势和视线。

05

UI 验证

放入真实计划与课堂，校正安全区、尺寸和注意力。

作品集中可以把你的实际生产方式补在每一步下方，例如“AI 草图探索 / 3D 角色精修 / 动效师协作 / UI 设计验收”。重点展示你控制了什么，不必展示所有提示词。

04 · STATE SYSTEM

同一位老师，
在不同任务中使用不同状态。

状态不是为了丰富动作数量，而是让学生在每一个时刻都知道老师正在做什么。

COMPANION

陪伴

规划、等待和鼓励。退后站位，低存在感。

TEACHING

教学

讲解、示范和反馈。进入内容侧边，与任务同场。

WAITING

等待

学生独立思考时，不动作、不打断，只保留低频存在感。

05 · MOTION LANGUAGE

动作表达教学状态，
不制造注意力噪音。

动效的核心原则是短、轻、可中断。角色不应该持续表演，它只在需要被感知的教学节点发生变化。

01

出现

计划生成、讲解开始时进入。300–500ms，单次完成。

ENTER
02

思考

学生停留后轻微观察内容，1–2 秒后停止。

THINK
03

讲解

视线和手势指向内容区，避免遮挡题干和答案。

TEACH
04

鼓励

完成任务后短促点头或庆祝，作为学习节奏的收束。

REWARD
“先别急，我们换个思路。”
06 · VOICE INTERACTION

语音只负责
推学生继续思考。

它不是长讲解的替代品。语音负责建立陪伴和启发，完整教学内容仍需要由学生主动展开。

SIGNAL

识别停留

连续错误或停留 8 秒，触发“可能需要帮助”的信号。

APPEAR

短动作回应

角色用 1–2 秒动作表达“我注意到了”。

VOICE

一句引导

提出问题、提示方向，不直接报出答案。

CONTROL

用户展开

完整讲解、音量和关闭权始终交给学生。

EXIT

自动收起

提示结束即回到低存在感，课堂主任务不被覆盖。

02
DESIGN SPECIFICATION

让角色和 UI，
在每一次使用中
保持一致。

规范不是整理设计稿，而是把视觉判断变成可被复用、协作和持续扩展的规则。

07 · VISUAL FOUNDATION

先规定空间、色彩与层级，
再放入内容和角色。

基础规范保证不同页面即使内容变化，也仍然属于同一堂课、同一个产品。

COLOR

空间蓝

课堂背景和内容氛围使用低压迫感的蓝色层次。

ACCENT

行动橙

只服务于确认、强调和关键教学反馈。

CONTAINER

稳定内容区

题目、讲解和操作都进入高对比的内容容器。

HIERARCHY

题目优先

课堂里任何角色、动效和提示都不得超过主任务层级。

08 · IP USAGE SPEC

角色在 UI 中的尺寸、位置和安全区，
都必须被明确规定。

角色好看不等于能放进产品。它需要对不同尺寸、不同背景和不同内容密度保持可用。

SAFE AREA

不进入题目和操作安全区

角色只能占据课堂侧边或背景留白，不能遮挡内容容器。

SCALE

尺寸随任务优先级变化

引导页可以更大；课中维持侧边小比例；提示结束后降低存在感。

BACKGROUND

背景服务角色，不反客为主

使用低对比空间和轻阴影，确保角色融入，而不是像贴在界面上。

DO / DON'T

有状态才出现，无状态不装饰

不要为了填补空白加入角色；出现必须对应明确教学目的。

09 · COMPONENT STATE SPEC

课程卡片
是一套完整的生命周期。

从生成到开课、完成、取消和异常，用户需要通过同一张卡片理解时间、状态和下一步行动。

未生成不可点击，解释状态
待开课突出最近课程和开始时间
进行中提供进入课堂或继续学习
已完成进入学习报告
异常状态取消、过期和退出均有明确反馈
10 · CLASSROOM & FEEDBACK SPEC

课堂框架不变，
内容和反馈才可以自由变化。

用稳定的内容容器和信息优先级，承接不同题型、不同讲解和不同反馈方式。

LAYER 01

题目与输入优先

题干、图形和答案区始终是课堂第一层。

LAYER 02

反馈就近出现

提示和讲解靠近对应问题，降低视线跳转。

LAYER 03

角色在侧边响应

老师参与课堂，但不改变学生的操作路径。

11 · TEACHING LANGUAGE SPEC

视觉层级，
替代学生的认知判断。

Highlight、Rewrite 和 Add/Remove 共同定义 AI 如何把复杂的推理，变成学生此刻能理解的教学信息。

HIGHLIGHT

意图不同，视觉不同

提及、提问和强调不再使用同一种高亮，学生能快速判断信息性质。

先观察这两个条件，你觉得哪里发生了变化？
记住：速度 × 时间 = 路程
REWRITE

系统语言改写为教学语言

不展示模型思考过程，只给出能够继续行动的下一步。

“先把已知条件圈出来，我们从最后一步往回想。”
ADD / REMOVE

变化不破坏布局稳定

动态提示进入和退出时，题目、输入和角色的空间关系保持稳定。

已知条件
老师刚刚补充的提示
下一步操作
SYSTEM IN PRODUCT

角色、动效和规范，
最后都要回到
真实产品。

课前角色陪伴计划生成，课程状态清晰可读
课中稳定课堂框架承接题型、语音和讲解
